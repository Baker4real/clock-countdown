# 五个界面与 AI 参考图的第一眼识别一致

## Problem Statement

当前实现虽然已经加入部分暖粉色 token、分格数字、徽章和装饰文案，但整体画面与 2026-09-10 的五张 AI 参考图仍有明显距离。用户第一眼无法把主窗口倒计时页、主窗口便签页、悬浮窗倒计时、悬浮窗便签和提醒中心识别为同一套界面。差距来自整体外壳、空间分区、标题和页签位置、内容卡片比例、玩偶与装饰落点、控件几何、字体层级和信息密度，而不是单一颜色值。

此前的增量调整缺少一个以真实运行截图为中心的试点闭环；现有捕获路径还会因全透明位图保护条件拒绝截图。没有可复核的真实画面，不能声称已经达到视觉目标，也不能把一次通过构建或静态 XAML 检查当作视觉验收。

## Solution

以五张 2026-09-10 AI 优化图为“第一眼识别一致”的视觉目标。AI 图优先决定所有可见视觉关系：窗口外形、标题和副标题位置、页签与命令区位置、装饰带顺序、玩偶锚点、卡片尺寸、控件形态、间距、字体层级和色温。现有业务语义、交互行为、数据模型、提醒规则、持久化、可访问性和安全边界继续服从项目契约。

视觉层使用真实 WPF 控件承载内容与交互，使用仓库现有的玩偶、装饰带和底纹 raster 资产进行裁剪、缩放、锚定和透明分层；不把整张 AI 截图当作可交互背景。允许重排或重写视觉层、ControlTemplate 和布局辅助代码，只要命令、数据和领域语义保持不变。

先以主窗口便签页为完整试点，使用隔离的确定性示例数据，在 1165×1350 设计坐标下拍摄真实运行截图。只有用户确认该试点达到“第一眼识别一致”后，才把规则扩展到另外四个界面。全部界面完成后，再拍摄真实 WPF v22 回归基线；AI 图不进入 manifest、哈希或像素门禁。

## User Stories

2. As a 用户, I want 窗口轮廓、主要分区和留白关系与目标图同构, so that 视觉相似性不依赖逐像素比较。
3. As a 用户, I want 深棕标题、浅棕正文、粉色和珊瑚强调保持统一, so that 信息层级清楚且画面温暖。

## Implementation Decisions

- **视觉权威**：五张 2026-09-10 AI 优化图是第一眼识别目标。AI 图之间出现差异时，按对应页面目标图分别实现；AI 图与旧视觉契约冲突时，AI 图决定可见几何和视觉关系。项目既有行为、数据、提醒、持久化、可访问性和安全契约继续有效。
- **视觉术语**：“第一眼识别一致”表示窗口外形、主色温、标题与导航位置、内容区块比例、装饰资产落点、主按钮和核心信息形态与目标图保持同构。允许文案数据、少量间距和图标细节有小幅差异，不允许改变整体识别关系。
- **真实交互层**：使用真实 WPF 控件承载正文、按钮、输入、列表和命令；通过自定义 ControlTemplate、布局辅助代码和语义 token 复刻目标图。不得把完整 AI 截图当作交互背景，也不得用静态图片遮挡可操作内容。
- **资产策略**：优先使用仓库现有的玩偶、装饰带、底纹和透明 raster，按目标图裁剪、缩放、锚定和分层。允许在现有资产无法表达目标构图时增加新的本地资产，但不得依赖联网字体、远程资源或外部桌面背景。
- **主窗口页面**：倒计时页和便签页分别对齐各自 AI 图的标题区、页签、装饰带和内容区块顺序；共享颜色、字体、控件语言和行为入口，但不强行共用页面排布。
- **主窗口便签试点**：先完成目标图中的头部卡片、页签与命令区、装饰带、新增便签卡、未完成/已完成分段、日期分组和便签卡。试点使用隔离确定性数据，不写入真实设置；用户确认后才扩展其他界面。
- **主窗口倒计时页**：保留名称、截止日期、时分秒、标签、提醒规则、显示设置和倒计时列表能力；单选组映射为不提醒=清空规则、按时间提醒=到点 absoluteOnce、自定义提醒=打开现有 0 至 8 条规则编辑器。输入图标、占位文、主按钮、期待文案、静态日间标识和底部当前主题文字按目标图实现。
- **主窗口便签页**：并排显示未完成/已完成和数量徽章；每个日期分组独立收放；便签卡采用复选框、正文/提醒、日期印记、标签和编辑/删除/“…”操作的目标图空间关系；“按日期分组”保留可见占位入口。
- **悬浮窗外壳**：保留 520×390 尺寸、拖拽、透明装饰命中边界、顶部玩偶、托盘/管理/退出命令和工作区切换语义；在窗口内部重建目标图的 pastel 场景与外壳层，不依赖用户桌面背景。
- **悬浮窗倒计时**：主项使用粉色底、粉红强调轨、数字色块分格、单位字和“超期待！”徽章；次项使用次级色块和单列规则线；月薪大于零显示今日已赚，否则显示固定鼓励文案；标题和页签按倒计时目标图排列。
- **悬浮窗便签**：标题按目标图显示“今日便签”；快速新增默认收起，由底部“＋ 添加便签”原地展开；底部设置按钮打开主窗口；便签卡使用右侧 pastel 日期印记和“…”入口；搜索、完成、日期、提醒、标签和新增语义保持不变。
- **提醒中心**：采用高留白白底和暖黄条目卡；顶部显示标题、数量和全部已读；来源图标、待处理徽章、计划时间和两行按钮按目标图布局；全部已读只是逐条知道了的批量封装，不新增状态字段。
- **静态主题标识**：应用仍为单一日间主题，不提供主题切换；为对齐 AI 图，主窗口可见“日间”和“当前主题：日间”静态信息，但不恢复主题循环按钮或夜间资源。
- **行为保留**：不改变倒计时、便签、标签、筛选、提醒规则、occurrence/cursor、稍后提醒、完成动作、设置备份恢复、单实例、托盘、拖拽、Tab 顺序和办公室部署契约。
- **实现顺序**：先修复或替换真实 WPF 捕获路径，再完成主窗口便签试点；试点截图经用户确认后，按页面目标图扩展主窗口倒计时、悬浮窗倒计时、悬浮窗便签和提醒中心；全部完成后重拍 v22。

## Testing Decisions

- 测试只检查用户可观察行为和真实渲染结果，不测试具体控件树或私有实现细节。
- 最高 seam 是真实应用启动、加载隔离确定性夹具、完成首帧渲染并截取窗口；该 seam 同时承载第一眼识别检查和有限几何检查。现有 C# 互操作、UI 回归、源代码契约和发布验证继续作为行为与发布回归 seam。
- 视觉验收分两层：第一层由用户对代表态截图做第一眼判断；第二层检查窗口轮廓、主要分区、标题/页签/装饰带相对位置、主卡片尺寸、按钮与数字块形态、色温和字体层级。AI 图不设逐像素阈值。
- 试点必须固定为主窗口便签页、1165×1350 设计坐标和隔离示例数据；必须覆盖头部、页签、装饰带、新增便签区、未完成/已完成分段、日期分组和至少四种便签卡。
- 透明装饰层不能使截图退化为全透明位图；捕获路径必须对真实 WPF 内容生成可审查画面，并保留透明层的命中测试语义。捕获失败时必须报告原始错误，不得以空白或伪造截图代替。
- 试点通过后，五个界面全部完成时重拍 v22：主窗口 8 帧（倒计时/便签 × 空态/代表态/压力态，加便签编辑态和筛选弹层态），悬浮窗 4 帧（倒计时、长便签顶部、长便签底部、搜索展开）。v21 仅作为归档，AI 图不进入 manifest。
- 行为回归覆盖：三态提醒规则映射、分段切换、日期分组收放、筛选和搜索、便签新增/编辑/删除/完成、悬浮窗展开/收起、日期 pastel 轮换、提醒中心全部已读、稍后提醒、失败重试、主题迁移和真实设置指纹守恒。
- 发布前执行项目规定的低影响完整验证组合；构建、测试、截图或发布契约覆盖的文件变化必须同步检查对应静态哈希和 `git diff --check`。本地构建成功不等同于视觉或办公室验收成功。

## Out of Scope

- 逐像素复制 AI 生成图，或把 AI 图直接登记为视觉基线。
- 改变倒计时、便签、标签、提醒规则、occurrence/cursor、持久化 schema、备份恢复和单实例语义。
- 新增主题切换、夜间主题、动态主题选择或恢复夜间资源。
- 用整张截图遮挡交互控件，依赖联网字体、远程图片或用户桌面背景来完成视觉效果。
- 改变悬浮窗 520×390 外壳的用户操作语义、托盘命令、拖拽和命中测试边界。
- 在试点尚未获得用户确认前扩展剩余四个界面。
- 办公室部署、远端传输、发布分支、第三方通信或用户真实设置数据变更。
