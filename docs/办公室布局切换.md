# 办公室布局切换

办公室的安装还是现有布局：登录任务 `Minmin Countdown` 经 pwsh 运行安装根里的 adapter `敏敏子倒计时.ps1`，桌面上是启动器 `敏敏子倒计时.exe`（可能还有遗留的 `.cmd`），也可能另有遗留任务 `敏敏子倒计时`。新布局里登录任务直接启动 `app\MinminCountdown.exe`，桌面上是快捷方式 `敏敏子倒计时.lnk`，安装根里只有程序目录 `app`、运行状态回执和用户数据。新部署入口 `Deploy-CountdownProgram.ps1` 接手办公室之前，先做一次布局切换（#287）。执行在 #289，要用户当场同意。

切换脚本是仓库根的 [Switch-CountdownInstallLayout.ps1](../Switch-CountdownInstallLayout.ps1)，经新部署入口运行：

- `-LayoutSwitch`：与部署走同一流程（预检、打包、只读探测、传输、安装、状态读取、本地记录），包里另带切换脚本，安装一步在办公室上运行它。
- `-LayoutRollback`：一次远端写操作，运行办公室上备份里的切换脚本副本，按备份回退。本机不需要构建输出，不打包、不传输。
- `-StatusOnly`：只读状态读取，切换前后都用它看办公室的现状。

切换脚本随部署包走，不单独作为一步远端脚本：它要用包里的新安装器和程序目录换布局，而脚本本身编码后约 9 万字符，远端执行入口一条命令只收 3 万字符。回退不依赖部署包，因为切换在备份时把切换脚本和新安装器 module 复制进了备份的 `tools\`。

## 前提

- **提权运行。** 切换和回退都要替换、删除计划任务，而办公室现有的 `Minmin Countdown` 是旧安装器在管理员 PowerShell 里注册的。远端步骤必须以提权身份运行；#289 的只读预检先确认远端步骤以什么身份运行。切换脚本在前置检查里只读地看当前进程是否提权（结果的 `install.elevated`），再按两个现有任务的 DACL 判断能否替换并删除它们。不能就停在 `precheck`，原因 `task-access-denied`，错误里写明是哪个任务，办公室什么都不变。
- 部署入口的常规前提：在干净、已推送的 `main` 上，同一提交有合格的套件记录与构建回执（见 [README](../README.md) 的 `Deploy-CountdownProgram.ps1` 条目）。
- 备份是安装根的完整副本，含用户数据与日志：安装根所在盘要有与安装根相当的空闲空间放备份。回退时还要在安装根旁边按备份再复制一份（约一个安装根大小），回退之后切换后的安装根整个留在备份目录的 `after-switch-*\root\` 里，直到备份目录被移走：要回退就按两到三个安装根的大小留空间。
- 切换期间应用停一会儿：从停下旧版本到新版本达到启动就绪。备份越大停得越久。

## 切换

1. 读状态：`pwsh -NoLogo -NoProfile -File ./Deploy-CountdownProgram.ps1 -StatusOnly`。现有布局下登录任务与新安装器的期望定义不一致（`status.loginTask.matchesExpected` 为 `false`）。留下这份输出，用来和切换后比较。
2. 切换：`pwsh -NoLogo -NoProfile -File ./Deploy-CountdownProgram.ps1 -LayoutSwitch`。即使探测读到当前提交已在现有布局里运行，切换也照常进行。办公室上的切换按顺序：
   1. 前置检查：没有别的安装、切换或回退在运行（切换取得全机安装锁，与新旧安装器同一把，一直持有到切换结束）；安装根存在；已有备份目录时要么完整可沿用，要么停下；任务权限够；新安装器 `-CheckOnly` 通过。
   2. 停下旧版本：按映像路径结束进程（结束每个进程前按 PID 重读映像路径与启动时间），不经计划任务停止（办公室的旧版本早于 #295，经任务停止会走崩溃路径）。
   3. 备份到 `<安装根>.layout-switch-backup`（默认 `D:\敏敏子倒计时.layout-switch-backup`），逐项核对哈希后最后写 `backup.json`。
   4. 经新安装器装入程序目录、更新登录任务、登记桌面快捷方式，并启动到启动就绪。
   5. 移除遗留：遗留任务、桌面上属于旧安装器的启动器，以及安装根里的旧文件。
3. 判读结果：`outcome` 为 `deployed`、`mode` 为 `layout-switch` 才算切换完成。这本身就是一次经新部署入口的成功部署：安装后的状态读取核对过提交、EXE 与运行中的进程，本地记录 `deployment-record.json` 的 `mode` 是 `layout-switch`。结果里的 `install` 是切换脚本的结果，要看：
   - `install.backup.directory` 与 `install.backup.action`：首次为 `created`，沿用上次的完整备份时为 `reused`。
   - `install.legacy`：`task` 为 `removed` 或 `absent`；`desktop` 逐个列出桌面启动器文件的处理，`removed` 已删，`absent` 本来没有，`kept-foreign` 是内容认不出、原样保留的同名文件；`unknownRootEntries` 是安装根里认不出、原样保留的条目。`kept-foreign` 与认不出的条目由用户决定去留。
   - `status`：提交是本次 HEAD，`running` 为 `true`，`loginTask.matchesExpected` 为 `true`。
4. 用户在办公室确认新版本正常运行、启动速度没有明显变慢。明显变慢或用户想回去时按下文回退。
5. 备份保留到用户确认不再回退为止。确认后由用户经受管回收把备份目录整个移走，不要永久删除。

用户数据不被移动或改写：`settings.json` 与两代备份、`settings-recovery-evidence`、`logs`、`holiday-cache` 切换前后逐字节相同。Windows 时间服务不碰。

## 切换停下时

结果是 `failed` 或 `unknown` 时，先看 `failedStep`、`install.failedStage`、`install.reason` 与 `nextStep`。`nextStep` 先给切换脚本自己的下一步，再说经部署入口怎么接着切换或回退。

| 停在 | 办公室的状态 | 怎么做 |
|---|---|---|
| `precheck`，`transaction-in-progress`（部署结论 `rejected`） | 没有改动；另一个安装、切换或回退正在运行 | 等它结束，先 `-StatusOnly`，`installInProgress` 为 `false` 之后再看其余各项，据此决定切换还是回退；它还在运行时不要再切换或回退 |
| `precheck`，`task-access-denied` | 没有改动 | 让远端步骤以提权身份运行，再切换 |
| `precheck`，`backup-incomplete` | 没有改动；已有备份目录，但没有完整的 `backup.json`（上次在备份途中被打断） | 确认里面没有要留的东西，把整个目录移走，再切换，切换会重新备份 |
| `precheck`，`backup-used-for-rollback` | 没有改动；这份备份已用于回退 | 要再次切换，先把备份目录整个移走（里面的 `after-switch-*` 是回退时留下的切换后文件），再切换 |
| `precheck`，其他原因 | 没有改动；安装根不存在，或新安装器 `-CheckOnly` 没通过（`reason` 是安装器给的原因，如交互会话不止一个） | 排除原因，再切换 |
| `backup` | 写了一半的备份已删除，旧版本经它的登录任务重新启动，其余没改 | 排除原因（如安装根里有文件被别的程序独占打开），再切换 |
| `install` | 备份完整保留；新安装器失败时自己回滚程序目录与登录任务，并重新启动旧版本（`install.rollback.outcome` 为 `rolled-back`） | 排除原因后再切换，会沿用这份备份（`install.backup.action` 为 `reused`）；或者回退 |
| `remove-legacy` | 新布局已装好并在运行；备份完整保留 | 再切换（沿用备份，重装同一版本，再移除遗留）；或者回退 |
| 结果 `unknown` | 不知道（连接在途中断开，切换可能还在办公室上运行） | 先 `-StatusOnly`：`installInProgress` 为 `true` 时切换还在运行，等一会儿再读，直到它为 `false`；它还在运行时不要再切换或回退。之后再切换：备份完整就沿用，备份不完整就停在 `backup-incomplete` |

部署入口自己的停下（预检的 `rejected`，以及 `probe-failed`、`transfer-failed`）发生在切换脚本运行之前，办公室没有改动；办公室上另一个运行在进行时的 `rejected` 见表中第一行。

## 回退

1. 回退：`pwsh -NoLogo -NoProfile -File ./Deploy-CountdownProgram.ps1 -LayoutRollback`。远端运行 `<安装根>.layout-switch-backup\tools\Switch-CountdownInstallLayout.ps1 -Rollback`，按顺序：
   1. 前置检查：没有别的安装、切换或回退在运行（回退同样取得全机安装锁并一直持有到结束），备份完整，任务权限够，只有一个交互会话（最后要在里面启动旧版本）。回退也要提权运行：切换后的登录任务是提权的切换注册的。
   2. 先让启动路径失效：移除现役与遗留登录任务，桌面上指向已安装 EXE 的快捷方式先复制到备份目录下的 `after-switch-<UTC 时刻>\desktop\` 再移除。之后任何一步停下，都没有启动路径能把应用从半恢复的安装根启动起来。
   3. 按映像路径停下新版本，结束每个进程前按 PID 重读映像路径与启动时间。
   4. 在安装根旁边按备份复制出 `<安装根>.rollback-staging` 并逐项核对，再把整个安装根改名为 `after-switch-<UTC 时刻>\root\`（切换后的程序目录、切换后改过的设置与日志都在里面），把这份副本改名成安装根。安装根要么还是回退之前的样子，要么不在，不会一半旧一半新。
   5. 按导出的定义恢复两个登录任务。
   6. 按备份恢复桌面启动器文件。
   7. 写 `rollback.json`，再经恢复的登录任务启动旧版本，等到启动就绪（与新安装器同一个就绪判定）。
2. 判读结果：`outcome` 为 `rolled-back`。`rollback.inert` 写三条启动路径（`currentTask`、`legacyTask`、`shortcut`）各做了什么（`removed`、`absent`，认不出的快捷方式 `kept`），`rollback.root` 按改名之前与备份的差别列出恢复、删除与保留的文件，`rollback.tasks` 写两个任务各做了什么（`restored`、`removed` 或 `absent`），`rollback.desktop` 写桌面文件各做了什么，`rollback.restartedProcess` 是重新启动的旧版本进程，`rollback.preservedDirectory` 是保留切换后文件的目录（没有要保留的时为空）。
3. 切换后改过的设置被切换前的设置替换，改过的那份在 `after-switch-*\root\settings.json`，要不要找回由用户决定。
4. 回退停下时（`failed`）看 `nextStep`：前置检查停下时什么都没改；之后停下时备份原样保留，登录任务与快捷方式已经移除（安装根可能不在，只差把 `<安装根>.rollback-staging` 改名过去），再次 `-LayoutRollback` 会沿用或重做那份副本，接着把安装根、两个任务与桌面启动器恢复成备份的样子。结论 `rejected`（原因 `transaction-in-progress`）时另一个运行在进行，回退什么都没改。结果 `unknown` 或 `rejected` 时先 `-StatusOnly`：`installInProgress` 为 `true` 时等它变成 `false` 再看其余各项；它还在运行时不要再回退或切换。回退可以重复运行。
5. 用过回退的备份不再用于切换。以后要再切换，先把备份目录整个移走，切换会重新备份。

## 备份目录

- `root\`：安装根的完整副本，路径、长度、修改时间与内容都和切换前相同。
- `tasks\current.task`、`tasks\legacy.task`：两个任务导出的整份定义（任务计划导出的 XML）。
- `desktop\`：桌面上的启动器文件（`敏敏子倒计时.exe`、`.exe.new`、`.cmd`，切换前就有的同名快捷方式）。
- `tools\`：切换脚本与新安装器 module，回退从这里运行。
- `backup.json`：最后写下，`complete` 为 `true` 才算备份完整。
- 回退之后另有 `rollback.json` 与 `after-switch-<UTC 时刻>\`：`root\` 是回退之前的整个安装根，`desktop\` 是回退移除或替换的桌面文件。回退被打断时安装根旁边可能留有 `<安装根>.rollback-staging`，再次回退会沿用或重做它。

## 不经部署入口回退

切换只经部署入口运行：它要用部署包，而部署包与暂存目录用完即删。回退不需要部署包，部署入口或远端执行不能用时，可以在办公室上用以管理员身份运行的 PowerShell 7 直接运行 `pwsh -NoLogo -NoProfile -File "D:\敏敏子倒计时.layout-switch-backup\tools\Switch-CountdownInstallLayout.ps1" -Rollback`。它输出的结果 JSON 就是上面的 `rollback`，判读同上。
