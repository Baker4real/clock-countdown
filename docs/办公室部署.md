# 办公室设备部署

## 唯一入口与实时状态

正式部署只使用 `Deploy-CountdownProgram.ps1`：

```powershell
pwsh.exe -NoLogo -NoProfile -File ./Deploy-CountdownProgram.ps1
```

只读查询办公室当前状态使用同一入口的 `-StatusOnly`：

```powershell
pwsh.exe -NoLogo -NoProfile -File ./Deploy-CountdownProgram.ps1 -StatusOnly
```

`-StatusOnly` 经主机受管入口执行 `Get-CountdownInstallStatus.ps1`，读取实时安装状态，不启停进程、不写部署记录，也不读取历史部署证据。输出包括载荷清单中的提交与聚合哈希、已安装 EXE 与清单是否一致、达到启动就绪的进程、登录任务是否符合期望、设置指纹、事务标记及 `installInProgress`。状态脚本自包含，办公室不需要预先安装项目脚本。

## 本机预检与部署流程

1. **本机预检，不连接办公室。** 只接受已推送且与 `origin/main` 一致的干净 `main` 当前提交。当前 checkout 的 `logs\suite-runs\` 必须有同一提交、开跑与收尾工作树都干净、收尾 HEAD 未变且整轮通过的记录；`Build`、`Core`、`CSharp`、`SourceValidation`、`InstallValidate` 五个必过阶段全部通过，Build 回执必须是带 `PayloadAggregateSha256` 的完整 `CleanR2R` 构建。当前 `app\published-payload.json` 必须属于 HEAD，且构建输出的聚合哈希等于该回执。两个安装器文件和全部 `BuildAssets.SourcePath` 还用 `git hash-object --no-filters` 与提交 blob 逐一核对，换行转换或源文件漂移会在连接办公室前以 `source-blob-mismatch` 拒绝。需要新证据时，先经低影响启动器运行：

   ```powershell
   pwsh.exe -NoLogo -NoProfile -File ./tools/Invoke-CountdownSuiteLowImpact.ps1 -Stage Build,Core,CSharp,SourceValidation,InstallValidate -Closeout
   ```

2. **节假日年度覆盖守闸。** 预检与实际 ZIP 打包入口从构建输出的 `app\holiday-data\` 读取随包年份；北京时间进入 12 月而缺少下一年数据时，在连接办公室之前以 `holiday-year-coverage-missing` 拒绝，并指出缺失年份和 `holiday-data/README.md` 的补数据流程。新安装器真实安装入口也在取得安装锁和调用任何 Windows port 之前执行等价守卫；`-CheckOnly` 按契约豁免。
3. **打包测过的字节。** 直接打包载荷清单列出的程序目录文件、清单、`Install-CountdownProgram.ps1` 与 `Countdown.Installer.psm1`，并在真实 ZIP 内生成根级 `package-manifest.json`，列出其余全部包文件与 SHA-256。打包时逐文件重算 SHA-256，任何文件在套件后变化都拒绝；不从提交重新导出，不重新构建，也不手工同步静态哈希。
4. **只读探测。** 经主机受管远端执行入口读取一次实时状态。若 HEAD 的同一份聚合哈希已在运行、EXE 与清单一致且没有事务标记，结果为 `already-running`，不传输也不重复安装。
5. **受管传输与安装。** 主机受管传输入口核对整包 ZIP SHA-256 并记账；远端写操作再次核对包哈希，解包后核对部署端注入的 `package-manifest.json` SHA-256，通过才启动包内新安装器。安装器在安装锁、中断恢复和任何 Windows port 之前验证全包精确闭包，改动、多出、缺少都拒绝。项目不选择连接程序、不探测长命令，也不保存连接参数或凭据。
6. **一次实时状态判定。** 安装后再次用同一状态命令读取；提交、EXE 哈希和启动就绪进程均符合预期才报告 `deployed`。安装结果或状态读取丢失时报告 `unknown`，不把未知当成成功或失败；先运行 `-StatusOnly`，若有事务标记则重新部署，让安装器先恢复。
7. **小型记录。** 每次通过本机预检的运行只保留一份 `deployment-record.json`，记录提交、包哈希、安装结果、状态快照和主机账本引用。主机账本仍使用 `transfer-attempts.json`；本票删除的是项目自有账本实现，不是这个现役文件或新链的 `-StatusOnly`。

进度写标准错误，结果 JSON 写标准输出。公开结果、记录和文档不得包含主机名、网络地址、账号、连接参数或凭据；连接由主机受管入口负责。

## 放弃的保护与替代

旧部署链的以下保护明确退役：

- 从提交重新导出源码、逐项核对构建输入并再重建一次；
- 项目自有 SSH 程序选择、长命令探测与传输账本；
- 严格成功回执 schema、部署 binding、两次独立回读和回滚前独立诊断 schema；
- 通过历史回执、旧包和旧账本交叉核对完成态。

不再保留第二套重建或旧证据 parser。替代保护是下面三项共同成立，而不是其中任何一项单独成立：

1. **套件起止干净且来源一致：** 同一提交、本 checkout，开跑与收尾工作树都干净，HEAD 在套件期间未变；
2. **干净构建回执：** 五阶段记录中的 Build 是完整 `CleanR2R`，不是增量构建；
3. **部署字节一致：** 部署时构建输出的聚合哈希等于该回执，Git 来源包文件匹配提交 blob；打包逐文件核对 SHA-256 并生成全包清单，传输、清单绑定和安装精确闭包确保送出的就是套件测过的那份。逐项静态钉值接替见 [发布完整性接替门与静态钉值退役对照](agents/release-integrity-replacement.md)。

实时状态读取替代成功回执、binding 与独立回读对“当前运行版本”的判定；主机统一传输记账替代项目自有账本。安装器自身的失败回滚结果仍写入部署结果，但不再生成旧的独立回滚前诊断格式。

## 历史证据边界

`docs/evidence\`、既有仓外运行证据及历史部署大包、解压树、回执、回读、诊断和账本全部原样保留，只供人查阅；本票不清理、不改写、不迁移格式。新入口不扫描或解析这些旧格式，也不把新记录写入旧证据根。新链的 `deployment-record.json` 与主机 `transfer-attempts.json` 是现役记录，同样不属于历史清理对象。
