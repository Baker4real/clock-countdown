# 办公室设备部署

使用 `Deploy-OfficeCountdown.ps1` 部署到 Tailscale 中的办公室设备。脚本只允许从干净且已推送的 `main` 部署：先验证 Git 状态、生成 Windows 字节格式安装包并核对 canonical 发布契约中的 SHA-256；源码包同时包含部署控制器，解压预检会逐项核对所有声明源文件，远端再用整个 ZIP 的 SHA-256 覆盖这些源码。正式部署时再检查 Tailscale 连通性，直连或官方 DERP 中继均可，并通过受管 SSH helper 上传。远端验收在全机安装事务锁内完成；安装器会原子写出独立的延期提交回执，即使 stdout 被截断或无法解析，部署端仍能定位并回滚候选事务。桌面路径按 Explorer 所属用户的 SID 注册表环境解析，不使用 SSH 身份的环境变量；远端与安装器会交叉核对用户、会话和桌面路径，变化时不创建事务，并在最终提交前再次核对。设置等价基线取自旧应用停止后的事务快照，因此远端测试与校时期间完成的用户保存会进入受保护基线，不会被更早的读数误判为部署篡改；最终设置读取、等价验证和事务提交持有应用保存使用的同一把跨进程写锁，关闭了读取到提交之间的竞态。事务直到哈希、设置等价、WPF 验证、计划任务和本次启动回执都通过才提交；提交动作还会再次核验桌面启动器仍等于事务记录的候选 SHA-256。任一步正常失败都会由同一事务恢复原安装目录、两个计划任务、桌面启动器（含 `.new` 暂存）、遗留 `.cmd` 启动器和 Windows 时间服务状态。损坏 journal 或缺失备份会停止在安全边界；候选期间若用户替换桌面文件，事务会恢复应用、任务和时间服务，保留用户文件与 journal 证据，并拒绝把部署误报为成功。

硬约束：发起端与办公室设备都必须运行 PowerShell 7+（`pwsh.exe`）。部署脚本和安装器会拒绝 Windows PowerShell 5.1，不提供 fallback。

远端安装主体不得内嵌到 `ssh.exe` 的命令行。部署器会把长脚本以 UTF-8 无 BOM 写入本次 `run-evidence` 目录，计算 SHA-256 后经同一组严格 SCP 参数上传；办公室端先复核脚本哈希，再用短命令执行 `pwsh.exe -File remote-install.ps1`，并把非零退出码传回发起端。这既保留了脚本完整性，也避免触发 Windows 进程命令行长度上限。

若部署失败，原本已使用 `pwsh.exe` 的计划任务会恢复原状态；检测到遗留 `powershell.exe` 任务时，回滚会改为当前已验证的 PowerShell 7 路径，以保持该硬约束。Windows 时间服务的启动类型和运行状态会恢复；已经发生的网络校时不尝试倒退。

必须使用脚本生成的 Windows 工作树字节包，不要改用 `git archive`；在本项目的 Windows `core.autocrlf` 环境下，后者可能改变脚本字节并使安装器 SHA-256 校验失败。

部署默认保持既有 `settings.json` 原样。唯一允许的例外是旧版 schema v3-v8 自动迁移到 schema v9：v3-v6 按既有规则补齐标签、日期和关闭状态提醒；v7 的关闭提醒迁移为 `{ "type": "none" }`，循环提醒迁移为 `repeat`，其首次到期时间严格等于旧起点加一个间隔；v8 的标签、日期和提醒对象原样保留。v3-v8 都只允许新增 `themePreference: "Auto"`，不得伪造手动日间或夜间。倒计时、便签原有字段、标签关联、显示精度、工资和上下班时间必须保持等价；部署不得为历史便签伪造日期、擅自开启提醒或改变首次到期时间。任何其他设置变化都会视为验收失败并触发回滚。

部署前先做本地预检：

```powershell
pwsh.exe -NoLogo -NoProfile -File .\Deploy-OfficeCountdown.ps1 -ValidateOnly
```

正式部署：

```powershell
pwsh.exe -NoLogo -NoProfile -File .\Deploy-OfficeCountdown.ps1
```

`-ValidateOnly` 会先验证工作树干净且当前分支为 `main`，再运行 `git fetch origin main` 更新 `origin/main`；随后核验本地 `HEAD` 与远端一致、Windows 工作树字节包和安装器 SHA-256 清单。它不会加载 SSH helper、连通办公室设备或执行远端命令。

正式部署不再依赖固定睡眠时间或旧的 PID 文件。安装器在启动前生成唯一令牌；悬浮窗首次完成渲染后写入带令牌、进程、交互会话、脚本路径和日历状态的回执。部署只要求 `window-ready`，日历仍可处于 `Pending` 或 `Unavailable`，因此网络日历不可用不会冒充启动失败；节假日日历请求在首帧之后异步进行，不会阻塞悬浮窗显示。

脚本会将本次包和哈希证据保存到 `D:\Codex\.codex\run-evidence\clock-countdown-deploy\`。它不复制、打印或提交 SSH 密钥和办公室设备凭据；连接配置仅由本机受管 helper 提供。
