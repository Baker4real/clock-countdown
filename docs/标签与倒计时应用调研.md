## 结论先行

本项目要优化的是两项主功能：**倒计时**与**便签**。标签不是第三个工作区，也不是仅用于着色的装饰；它是一套由两类记录共用的轻量组织与筛选能力。当前倒计时保留“进行中、到期”的时间语义，当前便签保留“未完成、已完成”的任务语义；正计时、归档等后续状态尚未实现，标签不改变任何一种状态。

当前实现只加入共享标签，不另做分类树、层级标签或跨类型混合列表。当前“倒计时 / 便签”切换已经承担一级归属；标签用于把同一主题下的两类记录关联起来，例如在各自列表里分别查看“工作”标签的倒计时和便签。不要让倒计时名称承担 `#标签` 解析规则；便签也优先用结构化选择器，避免 140 字符的正文承担隐藏语法。

标签调研的核心结论得到以下一手资料支持：

| 参考 | 已核实模式 | 对本项目的取舍 |
| --- | --- | --- |
| [Memos 标签文档](https://usememos.com/docs/usage/tags) | 从自由文本自动抽取 `#tag`，并可把标签与未完成任务等属性组成保存筛选。 | 适合长文本便签；不适合当前 140 字符便签和唯一名称的倒计时。解析正文/标题会把用户内容和分类规则耦合。 |
| [Joplin 搜索文档](https://joplinapp.org/help/apps/search/) | `tag:a tag:b` 表示同时拥有，`any:1` 表示任一，`-tag:a` 表示排除，`-tag:*` 可查无标签项。 | 它验证“任一 / 全部 / 无标签”必须有清晰语义；当前实现只做这三项，把排除和查询语法留到确有大量记录时再评估。 |
| [Plane 标签文档](https://docs.plane.so/core-concepts/issues/labels) | 标签有名称和可选颜色；可在详情页直接创建，也可在统一页面增删改。 | 倒计时和便签的新建/编辑都应允许搜索、选择或立即新建标签；管理动作可从选择器或筛选弹出层进入，不建立独立标签工作区。 |

推荐的最小数据与交互边界：

- 全局标签库：`id`、唯一名称、可选颜色；倒计时和便签都持有多个 `tagIds`，而不是复制标签文本或用颜色冒充标签。颜色只辅助扫读，不能承载筛选语义。
- 新建/编辑：两类记录共用多选标签选择器；标签管理从选择器或筛选入口进入，避免形成第三个独立标签工作区。当前实现支持创建、改名、删除和关联，不承诺颜色编辑或保存筛选。
- 列表：标签只筛选当前工作区，不把倒计时与便签混在一张结果列表。管理窗口的倒计时卡片和便签行显示全部关联标签，并随可用宽度自动换行；悬浮摘要不显示标签芯片，但仍应用共享标签筛选。
- 管理：标签改名同时作用于两类记录；删除标签只解除关联，不删除倒计时或便签。删除前会要求确认，但当前确认文案不显示受影响记录数；颜色编辑可在后续需求明确后再评估。

## 标签功能的统一体验决策

### 当前实现只做标签，不做分类

倒计时与便签继续是两个一级入口，这已经是用户可理解的稳定分类。当前实现只增加一套共享标签词表和一个跨入口的标签选择器，不增加 `分类` 字段、文件夹树、标签层级或独立“标签页”。这样既能让“工作”“学习”“家庭”跨两类记录复用，又不会把倒计时的时间属性和便签的完成状态塞进同一模型。

未来只有在用户确实需要让每条记录拥有唯一、长期的主归属时，再评估单选分类；那时分类也必须与多选标签明确区分，不能以同一个字段兼任两种含义。

### 标签应出现在哪里

| 位置 | 倒计时 | 便签 | 共同规则 |
| --- | --- | --- | --- |
| 管理窗口的新建/编辑区域 | 在名称和目标时间旁提供标签选择器。 | 在正文输入旁提供同一选择器；主窗重置新增编辑器时，以当时的筛选标签初始化。 | 可搜索、可多选、输入新名称即可创建；不要求用户先进入管理页。 |
| 当前工作区的列表 | 显示规则遵循上文列表边界，仍优先显示剩余时间、目标日期和到期状态。 | 显示规则遵循上文列表边界，仍优先显示复选框、正文和完成状态。 | 标签芯片只用于展示；筛选通过顶部筛选弹层完成，不跨类型混合结果。 |
| 顶部筛选条 | “全部 / 无标签 / 已选标签”，可与“进行中 / 已到期”叠加。 | “全部 / 无标签 / 已选标签”，可与“未完成 / 已完成”和正文搜索叠加。 | 同一标签词表可在切换工作区后复用已选条件，但每个页面只展示自己的记录类型；多标签可明确切换“任一 / 全部”。 |
| 悬浮窗 | 复用当前工作区和当前标签条件，只显示进行中的倒计时。虚拟“距离下班”项目没有标签，选择任一标签条件时不显示。 | 复用当前工作区和当前标签条件，只显示未完成便签；切入便签工作区时，一行快速新增以当时的筛选标签初始化，后续筛选变化不会覆盖当前选择。 | 管理窗与悬浮窗使用同一筛选语义，不放标签管理、复杂组合筛选或跨类型列表。 |

### 筛选语义和状态叠加

1. 默认显示“全部”，单击一个标签即显示当前工作区中含该标签的记录。
2. “无标签”是准确术语，表示 `tagIds` 为空；不要称为“未分类”，因为当前实现没有分类字段。
3. 多选标签时提供显式的“任一 / 全部”切换：默认“任一”，需要同时命中时切到“全部”。[Apple Notes](https://support.apple.com/en-us/102288) 和 [Joplin](https://joplinapp.org/help/apps/search/) 都提供这两种可复核语义。
4. 记录须先满足标签条件，再满足本页状态条件：例如“工作 + 已到期”的倒计时，或“工作 + 未完成”的便签。当前实现不做排除标签、查询语言和保存筛选。

### 到期、完成、置顶、归档与悬浮视图

- **倒计时**：标签不改变到期语义。沿用当前“到期后留在管理列表、悬浮窗只显示进行中”的规则；后续若增加置顶、正计时或归档，它们是倒计时专属字段和排序规则。参考 [Countdown（Find Appiness）](https://apps.apple.com/us/app/countdown/id1403367428) 的按标签搜索/筛选和置顶，以及 [Countdown to Anything](https://play.google.com/store/apps/details?id=com.jupli.countdowntoanything&hl=en_GB) 的自定义标签、倒计时/正计时和精选小组件。
- **便签**：标签不改变 `isCompleted`。完整管理窗口沿用“未完成优先、已完成默认折叠”的规则，并在各状态内按较新日期和同日较新添加项优先显示；状态与日期分组可独立收起、展开。完成后保留原标签，便于在展开已完成项时回溯。归档是便签将来的独立动作，不应由勾选完成或删除标签隐式触发；[Google Keep](https://support.google.com/keep/answer/6262765?hl=en-GB) 也将归档与删除分开。
- **置顶**：当前没有因标签功能新增置顶。若后续加入，置顶应只影响各自列表内部的排序，不能让一个置顶便签跑进倒计时列表，也不能替代标签筛选。
- **悬浮窗**：当前使用“当前工作区 + 当前标签 + 当前状态”的小摘要。倒计时只显示匹配条件的进行中项目，不因标签筛选而重新显示已到期项目；便签只显示匹配条件的未完成项，勾选后从悬浮摘要移除，仍可在完整管理窗口的“已完成”折叠区按标签回溯。不要在悬浮窗中铺开全部标签或高级筛选面板。

## 倒计时体验优先级建议

### 当前实现：接入共享标签，不改变倒计时生命周期

1. 新建/编辑和管理列表已接入共享多选标签；悬浮摘要消费同一筛选结果但不显示标签芯片。“全部 / 无标签 / 任一 / 全部”由管理窗口筛选弹层控制。
2. 保持当前“未到期优先、到期留在管理列表、悬浮窗只显示进行中”的语义；标签不能使到期记录重新出现在进行中悬浮摘要中。
3. 管理窗口卡片的标签显示遵循上文列表边界，继续优先显示名称、剩余时间和目标日期。

### 后续再补强倒计时专属体验

1. 再评估置顶和手动排序，规则固定为“置顶优先，再按最近到期”，并且只作用于倒计时列表。
2. 再评估“普通事件 / 截止日 / 纪念日”模板和复制已有项目，减少重复输入。
3. 到期后的“正计时 / 归档或隐藏 / 删除”必须作为显式动作；提醒、重复、日历导入、同步和系统级 Widget 均不阻塞当前共享标签功能。

## 便签体验优先级建议

### 当前实现：保留快速记录，接入共享标签

1. 管理窗口和现有悬浮一行输入均使用同一标签选择器；主窗重置新增编辑器、悬浮窗切入便签工作区时，以当时的筛选标签初始化，用户可随后改选或清空，筛选条件后续变化不会自动覆盖当前新增选择。
2. 保持“未完成优先、已完成默认折叠”的当前规则；各状态内按较新日期和同日较新添加项优先显示，状态与日期分组可独立折叠；勾选完成后保留标签，展开“已完成”时仍能按标签回溯。
3. 管理窗口的便签行显示全部关联标签，并随可用宽度自动换行；悬浮窗列表保持紧凑，只显示复选框、正文、提醒和日期索引。当前未加入富文本、附件、层级任务或跨记录关联。

### 后续再补强便签专属体验

1. 只有在完成项积累后，再单独评估“归档 / 恢复”和便签置顶；完成、置顶、归档均不得由标签自动改变。
2. 若频繁需要跨应用捕捉，再评估全局快捷键或更小的快速记录窗；它应打开现有便签入口，而不是创建第二套便签系统。
3. 系统级便签 Widget、系统通知服务和同步均后置。当前应用内循环提醒不扩展为系统级后台能力。

## 风险与验收重点

- 共享标签、便签日期、三模式提醒和三态主题偏好已经将本地 `settings.json` 升级为 schema v9；必须继续保留历史配置迁移和原子写入契约，不能因后续修改丢失已有倒计时或便签。
- 当前到期记录会保留但新增/编辑要求目标时间晚于当前时间。若实现“正计时”或“归档”，需要先明确其状态模型，再修改输入校验，避免隐性改变现有行为。
- 当前提醒已验证未到期不触发、一次性离线补发及跨重启去重、重复提醒同周期只触发一次、显示失败后可重试、完成便签不触发及 UTC 时间规范化；它仍是“应用运行时”能力，不宣称为 Windows 系统级通知服务。
- 记录操作控件使用 `Tag` 传递记录 ID，标签选择器和筛选控件使用 `Tag` 传递标签 ID；持久化关联必须存入领域状态的 `tagIds`，不能覆盖现有控件事件契约。
- 验收应覆盖：两类记录的多标签筛选、无标签、改名/删除标签后的跨类型关联更新、迁移旧设置、倒计时到期/便签完成后的筛选结果、悬浮窗过滤，以及保存失败时界面状态仍保持不变。
