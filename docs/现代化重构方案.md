# 敏敏子倒计时 WPF 渐进升级与 Tauri 闸门方案

## 1. 决策背景与完成定义

父级 PRD 是 [GitHub #189：WPF 渐进式 UI 精致化与现代化（替代全面重写为先）](https://github.com/Baker4real/clock-countdown/issues/189)。本方案修订了 2026-09-20 的全面 Tauri 重写草案：C# / .NET 10 WPF + PowerShell 7 继续是生产基线，先按 #189 的批次改善真实界面和代码组织；Tauri + React + Rust 只在最后作为一个隔离切片与 WPF 改版对比。

WPF 渐进升级完成的条件是：

1. 快赢、动效与排版、原生外观、结构、离线节假日和真实 DIP 布局批次分别通过对应的真实 WPF 渲染、交互和回归证据。
2. schema v1-v10 可读、canonical schema v10 可写、两代备份、恢复证据、提醒 occurrence/cursor/disposition/snooze 和失败保留语义不变。
3. PowerShell 安装、`-ValidateOnly`、办公室部署、SCP 账本、事务回滚和独立远端回读合同不变；只在实际触达发布边界时更新契约哈希。
4. 每批都能从现行 WPF 发布路径回滚，不能把 candidate、dry-run、deployed 或 live verified 混为一个状态。
5. 所有适用检查经 README 的低影响启动器通过，`git diff --check` 无错误。

Tauri 闸门不是本方案的默认目标。#209 闸门已于 2026-10-09 按第 7 节的独立通过条件执行，决定停止全面重写，WPF 仍是唯一生产入口；闸门证据见 `docs/evidence/clock-countdown-issue-209-tauri-candidate/`。

## 2. 现行架构边界

```text
C# / .NET 10 WPF application
        │
        ├── MainWindow / FloatingWindow / ReminderCenterWindow
        ├── DesktopWorkspace / ReminderEditing / ReminderDeliveryCoordinator
        ├── SettingsStore / schema v10 / backup1 / backup2
        └── runtime-status.json / acceptance-status.json / diagnostic JSONL
        │
PowerShell 7 adapter、安装事务、验证套件、办公室部署与 SCP ledger
```

WPF 继续负责主窗口、`520 x 390` 悬浮窗、提醒中心、托盘交互、单实例激活和真实 Windows 渲染。PowerShell 继续负责薄启动 adapter、计划任务、安装事务、验证、部署和证据采集。任何批次都不能把文件系统、设置写入或 Windows 系统能力绕过这些现有 seam。

现有 module 的职责保持清晰：`DesktopWorkspace` 管理倒计时、便签、标签和筛选；`ReminderEditing` 管理隔离草稿与规则校验；`ReminderDeliveryCoordinator` 管理发生项、送达、退避和处置；`SettingsStore` 管理规范化、原子替换和恢复门；`FloatingTrayController`、`InstanceActivationServer` / `Client` 和 `StartupAcceptanceProtocol` 继续拥有窗口、托盘、单实例和启动回执合同。

## 3. 不变量与视觉合同

- 北京时间、schema v10、两代合法备份、设置损坏时“恢复备份 / 退出”、提醒 occurrence/cursor/disposition/snooze、单一提醒中心和持久化失败保留语义不变。
- `DESIGN.md` 是暖粉日间主题、窗口尺寸、控件命中区、字体、对比度、装饰 raster 和真实 WPF 渲染的唯一视觉合同。参考图只指导几何和层次，不承担业务或命中语义。
- 动效只使用透明度、颜色和 Transform，尊重系统动画开关，可从当前值打断；计时数字更新不能造成布局跳动。
- 依赖必须精确锁定并进入 self-contained 发布闭包；办公室验收仍区分上传、安装、提交、独立回读和 live verified。

## 4. 分批实施与回滚

### 阶段 0：基线冻结

保存现行 WPF 运行、schema fixture、视觉基线、发布清单和部署证据索引。此阶段不改变用户设置或生产入口；回滚点是现有 `main` 发布路径。

### 阶段 1：快赢

完成日期选择器裁切修复、空状态引导、页签层级和可感知交互（对应 #190、#192 及同批任务）。每项改动都通过真实 WPF 窗口和现有 UI/源验证；失败时恢复本批文件即可。

### 阶段 2：动效与排版

按统一资源 token 引入悬停、按下、弹出层和页签指示条过渡，收敛字号阶梯、放大倒计时数字并补字体回退（#194–#198）。`prefers-reduced-motion`/系统动画关闭时长为零，动画不改变布局。

### 阶段 3：原生外观

主窗口请求 Windows 11 圆角和系统阴影，Windows 10 不支持时保持可用；提醒中心和规则编辑器只评估 Mica/Acrylic，不改变主窗口和悬浮窗暖奶油主题（#200、#201）。

### 阶段 4：结构

先局部引入 WPF-UI 替换日期选择、下拉和确认对话框，再以 CommunityToolkit.Mvvm 改造提醒中心与规则编辑器，最后评估 H.NotifyIcon.Wpf 托盘替换（#202–#205）。每次替换保留自动化名称、键盘关系和提醒事务语义。

### 阶段 5：离线节假日

随包提供受许可证约束的年度数据；现行缓存、联网结果和随包兜底优先级必须写入并验证。缺少年份覆盖时继续显示“日历未就绪”，不估算工资（#207）。

### 阶段 6：真实 DIP 布局

从主窗口 Viewbox 缩放迁移到真实 DIP Grid 布局，保持窗口尺寸、首眼识别、命中区和可访问性合同（#208）。这是 WPF 路线的最后一个高成本批次，完成前不启动技术栈闸门。

### 阶段 7：Tauri 闸门切片

在 [#209：栈闸门：Tauri 悬浮窗切片与 WPF 改版对比](https://github.com/Baker4real/clock-countdown/issues/209) 中创建隔离的单窗口候选。它只读脱敏 fixture 或自己的临时设置，不接入生产计划任务、真实用户设置和办公室发布入口。通过或失败都保留 WPF 回滚路径。

## 5. Tauri 闸门候选架构

闸门可以评估 Tauri 2 + React + TypeScript + Vite/CSS Variables + Rust，但这些名称和版本只有在该切片获批后才成为依赖。候选实现必须把前端限制在显示、草稿和交互，把 Rust/Tauri 命令限制在显式的 typed boundary；不得从前端任意访问文件、Shell、注册表、计划任务或网络。

切片至少包含一个真实 WebView2 `520 x 390` 悬浮窗、一个 typed command/event、键盘和焦点路径、窗口边界夹回、托盘恢复与第二实例发现。它不能声称已经重建主窗口、提醒中心、设置迁移或办公室部署，也不能把浏览器截图、单元测试或 `ValidateOnly` 当作生产验收。

旧架构比较表把 Rust 标为“不推荐”，指的是立即全量迁移的成本和维护门槛不适合当前项目；本闸门只用来验证一个有界实验是否值得继续，不改变这个默认判断。若实验未证明视觉、交互和发布收益足以抵偿 WebView2、供应链和验证成本，项目继续沿 WPF 路线。

## 6. 发布与办公室边界

所有 WPF 批次沿用现行 self-contained、`win-x64`、发布清单、`Countdown.ReleaseContract.psm1`、事务验收和 SCP ledger。只有真实修改 `IntegrityHashes` 覆盖文件时才更新对应静态 SHA-256；本票只更新文档，不改变覆盖文件。

闸门候选的安装包、WebView2、Rust/前端资源和哈希只能作为 candidate/dry-run 证据保存。即便本机切片通过，也必须重新建立 Tauri 版本的安装、回滚、远端传输和独立回读证据后，才可能讨论 deployed 或 live verified；在此之前办公室继续部署 WPF。

## 7. 验证门禁

- 文档和索引：检查现行结论只写 WPF 渐进优先，Tauri 只写闸门候选；不得保留旧版把替代栈写成既定路线或把全面迁移写成已开始的现行表述。
- WPF 行为与视觉：通过 README「本机验证」低影响启动器覆盖改动面的 Build、Core、CSharp、Ui、SourceValidation、InstallValidate 阶段；真实窗口套件不直跑。
- 发布边界：若改到安装/部署或 `IntegrityHashes` 覆盖文件，运行对应 `-ValidateOnly`、哈希和 `git diff --check` 检查；本票不触达这些文件。
- Tauri 闸门：仅在 #209 任务中增加真实 WebView2、无障碍、性能、单实例/托盘、离线安装、回滚和资源释放证据，并独立记录 candidate、dry-run、deployed、live verified。

## 8. 当前状态和下一步

- 当前生产宿主仍是 C# / .NET 10 WPF + PowerShell 7；本方案不宣称 Tauri 已开始迁移或已经部署。
- #189 的 WPF 渐进升级批次已于 2026-10-09 全部完成并合入 main；#209 闸门已执行并决定停止全面重写，各票完成态以 GitHub 回写记录为准。
- 技术栈状态、Rust 解释和候选边界见 [技术栈决策](stack.md)；模块和 seam 见 [架构与语言迁移](架构与语言迁移.md)。
- 任何未来切换都必须有新版本的设置等价、真实运行、安装事务、办公室回读和可回滚证据；旧 WPF 入口在此之前保留。
