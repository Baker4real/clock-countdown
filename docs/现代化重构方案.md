# 敏敏子倒计时全面现代化重构方案

## 1. 目标和完成定义

本方案把应用运行时从 C# / .NET 10 WPF 全面迁移到 Tauri 2 + React + TypeScript + Vite + Tailwind CSS + Rust。迁移完成后，用户可见 UI、窗口宿主、单实例、托盘、开机启动、提醒调度和设置事务都由新应用负责；PowerShell 只保留为 Windows 安装、部署和验收工具，直到新发布链路独立稳定。

完成不以“新项目能启动”为准，而以以下证据同时成立为准：

1. schema v1-v10 数据可读取，canonical schema v10 可写，备份、恢复和失败保留语义不变。
2. 主窗口、悬浮窗和提醒中心通过真实 Tauri WebView 渲染，符合 `DESIGN.md` 的暖粉日间合同和现役视觉基线。
3. 单实例、托盘、开机启动、窗口位置、拖动、焦点恢复和第二次启动激活行为通过真实 Windows 进程验收。
4. 关键路径通过键盘、屏幕阅读器名称、焦点可见、对比度和 reduced-motion 验收。
5. 新安装包、离线 WebView2、设置迁移、失败回滚、传输账本和两次独立远端回读均通过。
6. 旧 WPF 生产入口已停止使用，旧 WPF 代码只有在所有兼容回归证据归档后才删除。

## 2. 目标架构

```text
React / TypeScript / Tailwind / CSS Variables
        │
        │ Tauri invoke、typed events、window labels
        ▼
Tauri 2 / Rust application core
        │
        ├── ApplicationSession
        ├── SettingsStore
        ├── ReminderDeliveryCoordinator
        ├── HolidayCalendar
        ├── InstanceActivation
        ├── TrayController
        ├── WindowManager
        └── StartupAcceptanceProtocol
        │
        ├── settings.json / backup1 / backup2
        ├── runtime-status.json
        ├── acceptance-status.json
        └── diagnostic JSONL
        │
        ▼
Tauri MSI/NSIS + offline WebView2 + PowerShell deployment controller
```

前端只处理显示状态、草稿、交互和动画；Rust 负责领域规则、写盘、窗口和系统能力。前端不能直接调用任意文件路径、Shell、计划任务、注册表或网络请求。

### 2.1 窗口模型

- `main`：完整管理窗口，承载倒计时、便签、标签、筛选和设置。
- `floating`：固定 `520 x 390` 的悬浮窗，承载倒计时和便签两个工作区。
- `reminder-center`：单一提醒中心，首次显示贴齐工作区右上，之后保留用户位置。
- 每个窗口使用独立 Tauri Webview window；不依赖 Tauri v2 的 unstable multiwebview 特性。
- Rust `WindowManager` 是所有显示、隐藏、激活、置前、拖动和边界夹回操作的唯一入口。

### 2.2 前端模块

```text
ui/
  src/
    app/                 # 路由、窗口启动和错误边界
    features/countdowns/ # 倒计时列表、编辑和分格数字
    features/notes/      # 便签列表、日期分组和完成动作
    features/reminders/  # 提醒中心和处置动作
    features/tags/       # 标签、芯片和筛选器
    features/floating/   # 悬浮窗两个工作区
    design-tokens/       # CSS Variables、颜色、尺寸、焦点和动效 token
    bridge/              # Tauri command/event 类型与协议校验
    accessibility/       # live region、键盘和自动化名称
    assets/              # 运行时图片；不包含参考图 manifest
```

### 2.3 Rust 模块

```text
src-tauri/src/
  app/                   # Tauri builder、命令注册和生命周期
  domain/                # countdown、note、tag、reminder、calendar
  persistence/           # schema、迁移、原子写入和恢复
  runtime/               # token、window-ready、finalized-ready、诊断日志
  windows/               # WindowManager 和窗口边界
  tray/                  # tray menu、restore、quit
  activation/            # single-instance 请求和确认
  validation/            # validate-only 和测试 fixture
```

## 3. 前端和后端通信契约

所有消息使用带版本的判别式对象，不能传递任意 JSON。

```ts
type UiCommand =
  | { type: "restore-floating"; requestId: string }
  | { type: "save-countdown"; draft: CountdownDraft }
  | { type: "save-note"; draft: NoteDraft }
  | { type: "ack-reminder"; occurrenceKey: string }
  | { type: "snooze-reminder"; occurrenceKey: string; untilUtc: string }
  | { type: "complete-note"; noteId: string };

type UiEvent =
  | { type: "state-snapshot"; schemaVersion: 1; state: ApplicationSnapshot }
  | { type: "state-changed"; schemaVersion: 1; state: ApplicationSnapshot }
  | { type: "startup-ready"; tokenHash: string }
  | { type: "operation-failed"; code: string; messageKey: string };
```

规则如下：

- Rust 对所有命令做 schema、权限、身份和当前状态校验。
- 前端只能通过 command 改变状态，不能本地伪造保存成功。
- 写盘成功后 Rust 才发送新的 snapshot。
- 发生失败时 Rust 保持旧状态，前端保留草稿并展示可重试错误。
- 日志不记录便签正文、倒计时名称、筛选值、设置 JSON 或凭据。

## 4. 数据迁移和持久化

第一阶段不改变用户数据格式。Rust `SettingsStore` 必须实现现有契约：

- 缺少主文件表示合法首次运行。
- 合法主文件始终优先于 backup 1 和 backup 2。
- 主文件损坏或不可读时，只显示“恢复备份 / 退出”。
- 恢复前保留原始可读字节证据。
- 恢复写入后必须从主路径回读并通过相同严格校验。
- 合法保存以同目录临时文件、原子替换和按设置路径命名的跨进程锁完成。
- 失败时旧主文件、内存状态、草稿和提醒条目全部保留。

迁移实现顺序：

1. 把现有 schema fixture、canonical JSON 和失败注入用例导出为语言无关测试向量。
2. Rust 先实现读取、规范化和 v1-v10 迁移，不接 UI。
3. Rust 与现有 C# 验证器做双实现比对，覆盖字段、UTC、rule ID、occurrence key、cursor、snooze 和备份行为。
4. 新 UI 只消费 Rust 已通过校验的 snapshot。
5. 新旧应用在同一份脱敏 fixture 上跑完整回归；不让新旧进程同时写同一真实设置文件。

SQLite 作为未来可选优化，只有出现可复核的数据规模或查询性能问题才单独立项；它不属于本次视觉现代化的前置条件。

## 5. 视觉实现方案

`DESIGN.md` 继续是唯一视觉合同，前端把其中的 token 映射为 CSS Variables：

- `--canvas-brush`、`--card-brush`、`--ink-brush`、`--body-brush`；
- `--pink-accent`、`--peach-rail`、`--main-action`；
- `--radius-card`、`--radius-pill`、`--focus-ring`；
- 数字色块、标签芯片、提醒条目和装饰文字的专用 token。

视觉层可以使用 CSS gradient、mask、filter、blend mode、SVG、Canvas 和 WebGL；业务文字和关键交互仍使用普通 DOM 控件，确保可访问性和测试稳定性。

动效约束：

- 常态只使用即时反馈和短距离过渡，不为高频计时刷新做持续动画。
- 计时数字变化不能触发整页布局抖动。
- `prefers-reduced-motion: reduce` 下关闭装饰性位移、缩放和视差。
- 60 fps 是悬浮窗目标；CPU、内存和首帧时间纳入桌面探针。
- raster 装饰只承担视觉层，不承担按钮命中、文本语义或状态。

## 6. Windows 能力

### 单实例和激活

Tauri single-instance 插件只负责发现第二实例；Rust `ActivationServer` 继续拥有版本化请求、scope identity、request identity 和激活确认。第二实例只恢复并聚焦悬浮窗，不打开管理窗口、不改变筛选和草稿、不写设置。

### 托盘和开机启动

- 托盘菜单提供打开悬浮窗、打开管理窗口、复位位置和退出。
- autostart 插件替换旧的登录计划任务入口；安装器必须记录注册状态和启动参数。
- 首次启动仍以真实悬浮窗首帧作为 `window-ready`，不是进程启动作为就绪。
- 设置等价和提交前验收通过后，以同一 token 写出 `finalized-ready`。

### 窗口和输入

- 悬浮窗除按钮、输入和滚动区外可拖动。
- 所有窗口位置按当前工作区夹回，不依赖固定显示器编号。
- Windows 缩放、键盘导航、焦点恢复和屏幕阅读器名称都必须在真实 WebView2 中验收。

## 7. 发布、安装和办公室部署

### 本地构建

```powershell
npm ci
npm run typecheck
npm run lint
npm run test
npm run build
npm run tauri build
```

Rust 侧同时运行：

```powershell
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets
```

### 安装包

- Tauri 生成 Windows MSI/NSIS 产物。
- 办公室离线环境使用 offline WebView2 installer 方案。
- 发布清单记录安装包、前端资源、Rust EXE、图标和 WebView2 安装器的 SHA-256。
- 不把 Node、Rust、npm cache 或源码树放入运行目录。

### 办公室部署

部署控制器继续遵守现有安全边界：

- 只接受干净且已推送的 `main`。
- 首次传输前解析受管 SSH/SCP 绝对路径并运行只读 echo 探针。
- 传输记录 bytes、耗时、MiB/s、Mbps、退出码和失败状态。
- 远端安装在事务锁内完成，候选失败必须回滚。
- 新应用写出启动、运行和验收协议回执。
- 提交后执行两次独立远端回读，交叉核对主机、用户、应用路径、版本、进程、设置指纹和启动回执。
- “已上传”“已安装”“已提交”“独立回读通过”分别记录，不能合并成单一成功字段。

## 8. 分阶段实施

### 阶段 0：基线冻结

产物：现有 WPF 运行基线、schema fixture、视觉基线、部署证据索引。

通过条件：当前生产行为和新方案的边界已记录；不修改用户现有设置；旧路径仍可回滚。

回滚点：无代码切换，保留现有 `main` 发布路径。

### 阶段 1：Tauri 技术切片

内容：创建 `ui/`、`src-tauri/`、npm lockfile 和 Rust toolchain；实现一扇窗口、一个 typed command、一个 typed event、托盘和单实例。

通过条件：Windows 真实运行；第二次启动可激活第一实例；托盘和退出可靠；WebView2 缺失时安装器给出可验证失败。

回滚点：删除新目录即可，生产仍使用 WPF。

### 阶段 2：Rust 领域和持久化

内容：迁移 schema、北京时间、倒计时、便签、标签、提醒规则、日历 occurrence、备份恢复和诊断日志。

通过条件：语言无关 fixture 与旧 C# 结果等价；失败注入、原子写入和恢复门全部通过。

回滚点：新 Rust 只读 fixture，不接真实用户设置；旧应用继续拥有写入权。

### 阶段 3：主窗口

内容：重建倒计时页、便签页、标签筛选、编辑器和状态区。

通过条件：真实 WebView2 截图、键盘、焦点、自动化名称和 `DESIGN.md` 基线通过。

回滚点：主窗口仍由旧 WPF 提供，Tauri 主窗口只在显式验证入口启动。

### 阶段 4：悬浮窗和托盘

内容：实现 `520 x 390` 悬浮窗、双工作区、拖动、位置保存、复位和托盘恢复。

通过条件：真实首帧、窗口边界、激活、第二实例和内容刷新后的手动位置均通过。

回滚点：旧 WPF 悬浮窗仍是生产入口；新浮窗只接受隔离 fixture。

### 阶段 5：提醒中心

内容：送达、失败重试、知道了、稍后提醒、打开来源和完成便签。

通过条件：每个 occurrence 的送达、cursor、disposition、snooze 和写盘失败状态与 schema 契约一致。

回滚点：关闭新提醒中心，保留 Rust 调度 fixture，不触碰真实生产设置。

### 阶段 6：安装和远端部署

内容：Tauri MSI/NSIS、offline WebView2、安装事务、办公室部署、传输账本和独立回读。

通过条件：本地 validate-only、隔离套件、办公室候选安装、失败回滚、提交后双回读全部通过。

回滚点：办公室继续部署旧 WPF 包；新包只作为 candidate 留存。

### 阶段 7：切换和清场

内容：切换桌面入口和开机启动，保留旧包回滚窗口；归档旧 WPF 证据后再删除旧宿主。

通过条件：新版本 live verified，设置指纹符合预期，旧入口不会复活，所有发布清单和哈希更新完成。

回滚点：在事务边界内恢复旧入口、旧启动配置和旧安装目录；不删除用户设置。

## 9. 测试门禁

### Rust 与数据

- schema v1-v10 迁移和 canonical 往返；
- rule ID、occurrence key、cursor、snooze 和时区；
- 主文件、backup 1、backup 2、恢复证据和原子替换；
- 写盘失败、锁冲突、损坏 JSON、截断 JSON 和未知字段；
- 便签、倒计时、标签和提醒事务的失败保留。

### React 与 WebView2

- 主窗口、悬浮窗、提醒中心真实渲染；
- Playwright 键盘、焦点、滚动、日期选择、筛选和错误反馈；
- screenshot baseline、首帧时间、悬浮窗刷新稳定性；
- reduced-motion、对比度、自动化名称和 live region；
- WebView2 缺失、版本过低和安装器离线分支。

### Windows 与发布

- 单实例激活及 request identity；
- 托盘恢复、退出和窗口位置；
- autostart 注册、启动参数和 `window-ready` / `finalized-ready`；
- MSI/NSIS 安装、卸载、升级和失败回滚；
- 包清单、SHA-256、SCP ledger、远端成功回执和独立回读。

## 10. 风险和处理

| 风险 | 处理 |
| --- | --- |
| Rust 重写领域逻辑产生语义漂移 | 先导出语言无关 fixture，旧 C# 与 Rust 双实现比对，UI 最后接入 |
| WebView2 版本差异 | 使用 Evergreen，安装阶段检查运行时，CI 用稳定和预览通道做前向兼容 smoke |
| 多窗口状态不同步 | Rust 维护唯一 snapshot；窗口只订阅事件，不各自持有持久化真相 |
| 新安装器破坏办公室事务 | 阶段 6 前不切生产；候选、dry-run、deployed、live verified 分开记账 |
| 视觉效果影响计时性能 | 设定首帧、60 fps、CPU 和内存预算；装饰层与动态内容分离 |
| 依赖供应链漂移 | lockfile、许可证清单、依赖审查和升级独立任务 |
| 旧 WPF 入口复活 | 新安装器清理旧启动任务/入口并通过独立回读证明现役路径 |
