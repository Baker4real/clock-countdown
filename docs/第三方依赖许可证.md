## 传递闭包与随包 notices

- `H.NotifyIcon.Wpf 2.4.1` 的现役 NuGet 传递闭包包含 `H.NotifyIcon 2.4.1` 和 `H.GeneratedIcons.System.Drawing 2.4.1`；三个包的 `.nuspec` 均声明 MIT 和源码提交 `bcaaabecf16566dd910a3798fe874014e251b28d`，但实际 `.nupkg` 没有许可证或 notices 文件。仓库因此保留该提交的[原始 LICENSE](third-party/H.NotifyIcon/2.4.1/LICENSE.md)，完整覆盖这三个同源包。`H.GeneratedIcons.System.Drawing` 的 `net10.0` 组还声明 `System.Drawing.Common 10.0.0`；当前 `net10.0-windows` 还原结果将其列入 `packagesToPrune`，由 WindowsDesktop 框架提供，没有独立的 `System.Drawing.Common` NuGet 包条目。发布不能依赖目标机 NuGet cache。
- `WPF-UI 4.3.0` 传递 `WPF-UI.Abstractions 4.3.0`（MIT）。WPF-UI 包的 `ThirdPartyNotices.txt` 还列出 `VirtualizingWrapPanel 2.0.6`、`fluentui-system-icons 1.1.242`、`.NET WPF 8.0`、`microsoft-ui-xaml 3.0` 和 `segoe-fluent-icons-font 3.0`；发布或重新打包 WPF-UI 时必须保留该 notices 文件，并遵守其中对 Segoe Fluent Icons 的 Microsoft Platform 使用限制。
- `CommunityToolkit.Mvvm 8.4.2` 包内同时附有 `License.md` 与 `ThirdPartyNotices.txt`；notice 包含 MVVM Light 和 ComputeSharp 等来源说明，必须原样随包保留。`WPF-UI.Abstractions 4.3.0` 也附有自己的 `LICENSE.md` 和 `ThirdPartyNotices.txt`，即使字节与 WPF-UI 相同，仍保留在对应包目录。
- `WPF-UI` 在 `ConfirmationDialog` 的窗口内使用局部主题与控件字典；DatePicker / ComboBox 家族通过 `WpfUiPickerStyles` 显式引用基础样式，并将主题 token 限定在样式资源中。完整控件字典不合并到 `Application.Current.Resources`。主题映射和行为边界见 [设计系统](../DESIGN.md#wpf-ui-局部主题边界-205) 与 [架构与语言迁移](架构与语言迁移.md)。

## 验收与更新规则

构建由 `Countdown.ReleaseContract.psm1` 的精确源码哈希和 `Build-CountdownApplication.ps1` 的发布清单共同约束。新增或升级包时应同时完成：

1. 在对应 `.csproj` 使用精确版本，并确认目标框架资产可用于 `net10.0-windows`。
2. 从官方 NuGet 元数据和上游仓库核对许可证、传递依赖与 notices；将证据链接更新到本文。
3. 重新生成 self-contained `win-x64` 发布包，独立回读 `published-payload.json`，确认依赖 DLL 与本节七个许可文件都进入闭包，且许可目标文件逐字节匹配来源哈希。
4. 更新受影响源码的 `IntegrityHashes`，运行 README“本机验证”规定的低影响套件，并以 `git diff --check` 收尾。

本文本身不替代包内许可证或 notices；发布产物仍以各包随附的许可证文件和 notices 为准。
